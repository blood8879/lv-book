# i18n guide (en / ko / es)

Lv Book ships in **English (fallback)**, **Korean** and **Spanish**. The first
device language that is ko, en or es (any region: es-ES, es-MX, es-419, ...)
wins; anything else gets `en` (`resolveAppLocale` in `lib/l10n/l10n.dart`).
There is no in-app language picker. Export documents (PDF/CSV/Excel/submission
package) follow the app language.

## Layout

```
l10n.yaml                     gen-l10n config (template app_en.arb, output lib/l10n/gen)
lib/l10n/src/<area>_en.arb    <- EDIT THESE (source fragments, one pair per area)
lib/l10n/src/<area>_ko.arb
lib/l10n/src/<area>_es.arb
lib/l10n/app_en.arb           generated by tool/merge_arb.dart (do not edit)
lib/l10n/app_ko.arb           generated (do not edit)
lib/l10n/app_es.arb           generated (do not edit)
lib/l10n/gen/*.dart           generated by flutter gen-l10n (committed, do not edit)
lib/l10n/l10n.dart            import this: context.l10n, l10nFor, l10nKo, resolveAppLocale
tool/merge_arb.dart           merges fragments; fails on duplicates / missing keys / bad prefix
tool/l10n.sh                  merge + gen-l10n + format   (tool/l10n.sh --check for CI)
test/l10n/                    key-parity, staleness, locale-policy and en/ko widget tests
```

## Workflow

1. Add the key to **all three** `lib/l10n/src/<area>_en.arb`, `<area>_ko.arb`
   and `<area>_es.arb` (the merge tool fails on a key missing in any locale;
   `test/l10n/l10n_es_test.dart` also checks placeholders/plurals match en).
   Put `@key` metadata (description, placeholders) in the **en** fragment.
2. Run `tool/l10n.sh`.
3. Use it: `context.l10n.<key>`.
4. `flutter analyze && flutter test --no-pub`.
   `test/l10n/l10n_test.dart` fails if `app_*.arb` / `gen/` are stale.

### Areas, owned files and key prefixes (parallel work)

Each worker edits **only its own fragment pair** and its own files. The merge
tool rejects a key whose prefix does not belong to the fragment's area, so two
workers can never create the same key.

| Fragment | Owns | Allowed key prefixes |
|---|---|---|
| `core` | `lib/app.dart`, `lib/core/**` (done) | `core` |
| `fieldbook` | `features/fieldbook/**`, `features/import/**`, `features/quickmemo/**` | `fieldbook`, `import`, `quickMemo` |
| `export` | `features/export/**` | `export` |
| `benchmark_project` | `features/benchmark/**`, `features/project/**` | `project`, `benchmark` |
| `settings_pro` | `features/settings/**`, `pro/**`, `purchase/**`, `ads/**`, `backup/**`, `lib/shared/**` | `settings`, `pro`, `purchase`, `ads`, `backup` |
| `peg_test` | `features/pegtest/**` | `pegTest` |

- **Do not edit `core_*.arb`.** Reuse existing `core*` keys (below) when the
  Korean text is identical; otherwise add an area key, even if it duplicates
  English text.
- Merge conflicts in `lib/l10n/app_*.arb` or `lib/l10n/gen/**` are expected
  when branches merge: **never hand-resolve them** — take either side and
  re-run `tool/l10n.sh`, then commit the regenerated files.

### Available `core` keys

`coreAppName` (Lv Book / 레벨 야장), `coreAppProName` (Lv Book Pro / 레벨 야장 Pro),
`coreCancel` 취소, `coreSave` 저장, `coreDelete` 삭제, `coreConfirm` 확인 (OK),
`coreAdd` 추가, `coreEdit` 수정, `coreClose` 닫기, `coreRetry` 다시 시도,
`coreProcessing` 처리 중, `coreSaved` 저장됨, `coreErrorWithDetail(error)` 오류: {error},
`coreSelectedCount(count)` (plural), `coreJudgementWithinTolerance` 적합 (long),
`coreJudgementOk` 적합 (short "OK"), `coreJudgementCheckRequired` 확인 필요,
`coreFileNotUtf8`.

## Key naming

- lowerCamelCase, area prefix first, then screen/feature, then element:
  `fieldbookEditSaveButton`, `exportShareTooltip`, `benchmarkStatusUsable`,
  `settingsRestoreDialogTitle`, `purchaseActivatedMessage`.
- Suffixes help reviewers: `...Title`, `...Button`, `...Tooltip`, `...Hint`,
  `...Label`, `...Message`, `...Error`, `...Confirm`.
- One key per meaning, not per Korean string; same Korean in two contexts may
  need two keys if English differs.

### Dynamic text: ICU, never string concatenation

```json
"fieldbookRowCount": "{count, plural, =1{1 row} other{{count} rows}}",
"@fieldbookRowCount": { "placeholders": { "count": { "type": "int" } } },

"exportSavedTo": "Saved to {path}",
"@exportSavedTo": { "placeholders": { "path": { "type": "String" } } }
```

ko: `"fieldbookRowCount": "{count}행"`. Korean has no plural forms, so the ko
side may use plain `{count}` or `{count, plural, other{...}}`.
Numbers that are measurements are formatted by the caller
(`value.toStringAsFixed(3)`, misclosure 4) and passed as `String`
placeholders, so decimals never change with locale.
Placeholders inside a message need the declaration in the **en** `@key`.

## Access patterns

### 1. Widgets: `context.l10n`

```dart
import 'package:lv_book/l10n/l10n.dart';   // or relative '../../../l10n/l10n.dart'

Text(context.l10n.coreCancel)
tooltip: context.l10n.exportShareTooltip,
```

- `const` must be dropped from widgets whose text becomes `context.l10n...`.
- `context.l10n` falls back to **Korean** when no delegate is installed
  (existing widget tests pump a bare `MaterialApp` and assert Korean text — they
  keep passing unchanged). Do not change those tests' expected Korean.
- In callbacks after an `await`, grab `final l10n = context.l10n;` **before**
  the await (or check `context.mounted`).

### 2. Non-widget code: take `AppLocalizations l10n`

PDF template, CSV exporter, submission package, backup service errors,
purchase controller messages, domain validation have no `BuildContext`.

Preferred, in order:

a. **Domain returns codes/enums; UI maps them to text.** Keeps domain pure and
   testable.

```dart
// domain
enum FieldBookStatus { draft, reviewed, needsCheck }
// ui (extension in the presentation layer, or a switch in the widget)
String fieldBookStatusLabel(AppLocalizations l10n, FieldBookStatus s) =>
    switch (s) {
      FieldBookStatus.draft => l10n.fieldbookStatusDraft,
      FieldBookStatus.reviewed => l10n.fieldbookStatusReviewed,
      FieldBookStatus.needsCheck => l10n.fieldbookStatusNeedsCheck,
    };
```

b. **Exceptions carry a code; expose `localizedMessage(AppLocalizations)`**.
   Example: `TextFileEncodingException.localizedMessage(context.l10n)` in
   `lib/core/utils/text_file_picker.dart`. A legacy `message` getter may return
   `localizedMessage(l10nKo)` while callers are converted.

c. **Generators take an `AppLocalizations l10n` parameter**; the caller passes
   `context.l10n` (so exports follow the app language):

```dart
static Future<Uint8List> generate(FieldBook fb, ..., {required AppLocalizations l10n})
// caller
await PdfTemplate.generate(fb, ..., l10n: context.l10n);
```

   Prefer a required named parameter. If a call site truly has no context,
   use `l10nForPlatform()` (device languages, same policy as the app).

d. **Notifiers/controllers** (e.g. `PurchaseController`) should expose a state
   enum/code and let the widget render it with `context.l10n`; if a message
   string must be stored, inject `AppLocalizations Function() l10n` defaulting to
   `l10nForPlatform`.

### 3. Tests / services

```dart
import 'package:lv_book/l10n/l10n.dart';
final en = l10nFor(const Locale('en'));   // English
final ko = l10nKo;                         // Korean (== l10nFor(Locale('ko')))
```

Widget test in a specific language:

```dart
MaterialApp(
  locale: const Locale('en'),
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  home: ...,
)
```

Full app (`LvBookApp`) uses the device language — pin it with
`tester.platformDispatcher.localesTestValue = const [Locale('ko', 'KR')];`
plus `addTearDown(tester.platformDispatcher.clearLocalesTestValue);`
(see `test/widget_test.dart`). Add at least one English assertion per
converted screen when cheap.

## Do NOT localize

- DB values, backup JSON keys/`kind`, file-format identifiers, preference keys.
- **CSV import must accept the headers/labels of every language** that any
  app version exported (older files are Korean). Export in the app language,
  import tolerant of all (`CsvImporter` derives the current `exportField*` /
  `exportColumn*` labels of every supported locale automatically).
- File names that other tools match on (keep ASCII; e.g. `lvbook_backup.json`).
- Station names and user-entered text.
- Debug/log strings and code comments.

Rules:

- **Never** "Fail", "Failed", "Rejected", "Pass/Fail" for misclosure judgement
  (Korean rule bans 불합격). Exceeding tolerance is a **warning**: wording like
  "Check required", "Exceeds tolerance — check the readings".
- Pro is a **one-time purchase**. Never "subscription", "subscribe", "per month".
- Units: app setting Metres / Feet (`LengthUnit`); never hardcode `m` —
  take `unit.symbol` ('m' / 'ft') as a `{unit}` placeholder. Readings are
  never converted. Tolerance is entered in mm (metres) or ft (feet). Same
  decimals as Korean: 3 (misclosure 4). No locale number formatting (no
  thousands separators, always `.` decimal).
- English PDF/CSV print intermediate sights in an IS column (BS | IS | FS);
  Korean exports keep the original layout. `CsvImporter` accepts both.
- Dates: data and exports keep `yyyy-MM-dd`; UI may stay ISO.
- Sentence case for buttons/titles ("Save level book", not "Save Level Book"),
  except proper names (Lv Book, Pro, BM, TBM).
- Keep it short — field users on phones; English is often ~1.5x longer than
  Korean, so check for overflow in tight rows/pills (prefer the short forms).

### Spanish rules

- **Neutral Spanish for Latin America + Spain.** Formal *usted* for
  instructions and messages ("Ingrese", "Toque", "Revise", "Elimine"), never
  *tú* / *vos*. Buttons and menu items use the **infinitive** ("Guardar",
  "Agregar", "Exportar varias", "Restaurar compra"). Prefer LatAm-neutral
  words that Spain also understands: "Agregar" (not "Añadir"), "Ingresar"
  (not "Introducir"), "Eliminar" (not "Borrar", except clearing a field:
  "Borrar todo", "Borrar" signature), "app", "Ajustes", "p. ej.".
- **Abbreviations.** Grid/table headers and sums use Spanish abbreviations
  everywhere (editor, PDF, CSV): **VAt | VI | VAd | AI | Cota** and
  **ΣVAt / ΣVAd / ΣAsc / ΣDesc** (keys `fieldbookColumnBs/Fs`,
  `fieldbookSummarySumBs/Fs`, `exportCheckSumBs/Fs`; en/ko keep BS/FS).
  The Σ labels must start with `Σ` (`CsvImporter` stops the table there).
  **BM, TBM and TP stay as tokens** in Spanish: the BM/TBM kind label, default
  BM names ("BM.1"), the sample stations ("TP-1") and the export remark marker
  'TP' are shared data across languages, and "BM" is the usual field term in
  Latin America. Prose spells them out once ("banco de nivel (BM)",
  "punto de cambio (TP)"). "BN"/"PC" are not used, to avoid two names for one
  thing on the same screen.
- Exports use the BS | IS | FS layout (VAt | VI | VAd) like English
  (`exportUsesIntermediateColumn` is false only for Korean).
- Judgement wording: never "Falla", "Fallido", "Rechazado", "Reprobado",
  "No apto"; exceeding tolerance is "Requiere revisión" / "Supera la
  tolerancia: revise las lecturas". Pro is a **pago único**; never
  "suscripción" / "al mes" (`test/l10n/l10n_es_test.dart` enforces this).
- Numbers keep `.` decimals in UI, PDF and CSV (no locale formatting). Note:
  the editor's reading fields parse with `double.tryParse` and do **not**
  accept `,`; only the tolerance and two-peg inputs do. Spanish phone
  keyboards that show `,` as the decimal key are a known gap.
- Spanish is ~1.2–1.4x longer than English: keep grid headers ≤ ~8 chars
  ("Pto.", "Asc/Desc", "Cota proy.") and check new screens at 360 px
  (`test/l10n/es_screens_test.dart`).

## Known gaps / not yet localized

- iOS permission prompts (`NS*UsageDescription` in `ios/Runner/Info.plist`)
  are Korean only; English needs `InfoPlist.strings` per `.lproj` added via
  Xcode. iOS `CFBundleDisplayName` is already "Lv Book" (same for both).
- Android launcher label: `res/values/strings.xml` (Lv Book) and
  `res/values-ko/strings.xml` (레벨 야장).
- Store listings: `docs/store/store-listing-en.md`, `store-listing-es.md`.
- iOS: `CFBundleLocalizations` lists en, ko, es; Android needs no
  `values-es` (the launcher label "Lv Book" is the same).
